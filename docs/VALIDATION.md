| 検証 | 結果 | 内容 |

| `npm test` | 15 / 15成功 | 2〜7人、4形式、ラウンド移行、未回答、タイマー有無・残り時間、早押し修正／誤答再開、パネル回数、再戦、途中終了、順位、公開データの分離 |

アクセス拒否を確認するテストでは `permission_denied` / `PERMISSION_DENIED` がログに出ます。拒否を期待するテストの正常な出力です。サービス接続層テストはViteのSSRローダー経由で同じbackend.jsを読み、実際のFirebase SDKとEmulatorで実行しています。ブラウザ操作を代替したとは扱っていません。

## 必須シナリオとの対応

| 仕様のシナリオ | 自動検証 |
|---|---|
| 回答者2人／7人、固定ラウンドの24／34問 | domainで全問進行・統計合計確認 |
| ○×・4択の確定、未回答、締切後の明示発表 | domain + Rules + 接続層の○×通し操作 |
| 4択の先頭正解・シャッフルID維持 | domain |
| タイマーあり／なし、切断時残り時間・手動再開 | domain、Rulesで期限・offline・paused拒否 |
| 早押し同時タップ | RTDB Emulatorの同時transaction、先着1名・上書き禁止 |
| 早押し誤答後再開・回答権修正 | domainで再押下禁止、旧回答権者の誤答不計上 |
| 早押し文字入力 | Rulesで当選者のみ／grantごと1回／再送禁止 |
| パネル全員判定・未回答・規定回数・未選択の履歴 | domainで7人各2回、未選択1マス未使用、得点自動加算なし |
| 途中終了 | domainで未完了は統計除外、使用履歴には残す |
| 再戦の履歴継続／リセット | domain + 接続層で実DB確認 |
| 問題不足 | domainで形式別・パネル全15マス条件 |
| 新規参加・退出・席数上限・開始ロック | Rulesでゲーム中拒否、7席上限、固定hostの兼任禁止 |
| 正解・問題文の発表前非公開 | domainの公開projection、Rulesでhostパス拒否 |
| 回答内容の本人／司会者限定 | Rulesで他人の回答・親パス拒否 |
| 得点・順位非公開 | Rulesでhostパス拒否、自分の正誤結果だけ取得 |
| 管理者にも他人の作問原本を非公開 | Firestore Rulesで管理者UIDを含め拒否 |
| ジャンル参照時削除禁止・改名時ID保持 | Firestoreの原子的参照カウンターと正規名前予約を検証 |
| 古い接続の切断通知 | Rulesでsession不一致offline更新を拒否 |
| private締切とpublic投影の間の提出競合 | Rulesでprivateが先にclosed／pausedの場合も回答拒否 |

## 実機確認の最短手順

- Emulator検証用会員を別ブラウザプロファイルで使い、司会1＋回答者2人で各形式を1ゲームずつ進行する。次に回答者7人のラウンド制を完走する。
- ○×／4択では全員確定と手動締切、タイマー有無を確認。発表前に他人の回答・正解をネットワーク取得できないことも確認する。
- 早押しを同時押下し、誤答→再開→回答者修正、文字入力の再送禁止を確認。音は司会端末だけで確認する。
- パネルの未回答者を残して締め切り、チェック判定後の個人結果と選択回数を確認する。
- 各受付中に司会端末の通信を切り、回答者の操作停止・席の維持・残り時間・手動再開を確認する。回答者自身の通信断とページ再読み込みでも確定回答が維持されることを確認する。
- 途中終了、再戦、履歴不足、確認付き履歴リセット、閉鎖後のコード無効化を確認する。

現状は本番インフラと公開URLを用意した初期実装です。これらの未検証項目を残したまま、本番の動作保証や全仕様の実機受入完了とは報告しません。
